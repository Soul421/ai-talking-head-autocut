# Video Script · Director Layer（短视频留存增强）

把已锁定的完整声音和字幕时间轴转成全片一致、可确认、可还原的导演处理稿。先回答“观众经历什么、画面世界如何演进”，再回答“每一段真实口播时间里发生什么”。

本 Skill 是逐字稿与实现管线之间的导演层。它不默认把所有内容做成 MG，也不把“运动优先”误解为“所有东西一直动”。真人、真实录屏、截图、B-roll、图形动画和留白都可以成为正确答案；关键是它们是否共同服务同一条叙事与注意力路径。

对短视频，本 Skill 可作为“爆款潜力导演”：它负责让镜头继续履行上游稿件的停滑、留存和传播意图，但不承诺流量结果，也不用画面替上游修稿。

## 职责门禁

- 正式视频导演稿必须同时具备：已确认逐字稿、已锁定完整音频、主字幕文件和校准后的带时间码字幕数据。只有选题、素材、大纲、逐字稿或 `8–15s` 声音试听时，先完成上游，不得进入正式分镜。
- 用户同时要求“写逐字稿＋做分镜”时，先完成当前工作区可用的上游逐字稿创作/审稿流程，再完成声音试听、完整配音、字幕生成和校准，最后把同一版本交给本 Skill。不要一边写正文、一边生成声音、一边预设画面。
- 不改写原稿的事实、观点、顺序、句子或连接词。发现口语、逻辑、事实或段间衔接阻塞制作时，引用具体相邻句，标为“上游逐字稿阻塞”，转回当前可用的逐字稿修订流程；若未安装专用 Skill，则明确告知用户需先修稿。用户明确要求按草稿原样继续时才做导演处理。
- 不输出 HTML、JSX、Remotion 组件、HyperFrames DOM 或 ChatCut MG 实体。实现属于下游 Skill。

## 执行职责

- 导演规划者完成导演诊断、素材职责、导演稿和制作规格；角色和能力要求以当前运行时与工作区指令为准，不在 Skill 中写死模型版本。
- 本阶段不得启动任何镜头执行者，也不得提前写场景代码。只有导演稿、制作规格、素材计划和 motion contract 锁定后，才交给已选管线的单一执行者；本工具包的 HyperFrames 执行者是 `hyperframes-scene-animator`。

## 单一导演来源

锁定后的 `导演契约 + beat graph` 是下游的叙事与视觉单一事实源。

- 下游可以补坐标、组件、帧、选择器、缓动和渲染细节。
- 下游不得擅自更换核心视觉命题、贯穿物、证据顺序、运动语法或转场关系。
- 实现不可行时，记录冲突与保守替代方案，返回导演阶段确认；不要静默重新导演。

## 默认保持管线无关

1. 用户未指定工具时，不选择默认实现工具，也不写 `pipeline`。
2. 使用真人、录屏、截图、B-roll、仿真 UI、流程关系、图形动画、空间和镜头等通用语言，不在导演契约中混入平台属性、坐标、帧号或组件名。
3. 用户明确指定 Remotion、ChatCut、HyperFrames、剪映或其他管线时，保留同一份导演契约，只追加最少必要的应用说明。
4. 能用真实证据直接说明的内容，不用抽象隐喻替代；抽象逻辑才优先寻找可演进的视觉隐喻。

## 按需读取

- 每次正式生成导演稿时读取 `references/director-treatment.md`。
- 导演方向锁定后读取 `references/beat-graph.md`。
- 完成导演稿前读取 `references/anti-ppt-gate.md`；写制作规格时在实现前再检查一次。低清 proof 后的语义运动、转场中点、AI 味硬拒绝项和联系表连续性由下游执行者检查；HyperFrames 管线使用 `hyperframes-scene-animator`。
- 正式交付时读取 `references/output-template.md`。
- 目标是短视频、平台分发型视频，或用户明确要求完播、留存、爆款/传播潜力时，读取 `references/short-video-retention-directing.md`；只提取稿件已有意图，不调用上游选题或片头改写流程。
- 中长视频、复杂剪辑判断或节奏诊断时读取 `references/editing-methodology.md`。
- 命中既有平台风险或用户要求复盘经验时读取 `references/lessons-learned.md`，只应用相关规则。
- 分镜已确认且用户要求继续制作时读取 `references/production-spec.md`。制作规格必须使用已经锁定的最终声音和带时间码字幕，并在代码动画管线中同步产出 `work/motion-contract.json`。
- 用户明确要求 HyperFrames 制作时：若尚无固定舞台工程，先读取 `talking-head-hyperframes` 生成模板与素材交接；交接状态为 `READY_FOR_EXECUTION` 后，一律读取 `hyperframes-scene-animator` 实现所有镜头。模板 Skill 不制作场景。
- 使用 Studio 暖白 Remotion 模板、沿用 J-space 视觉或用户锁定同类背景时，在给方向卡前用 `view_image` 查看 [Studio 暖白蓝金网格高清参考图](assets/references/studio-warm-grid-jspace-s06-1920x1080.png)，并按 `references/director-treatment.md` 把背景当作导演约束，而不是实现阶段再补的装饰。
- 需要实际生成图片时读取 `imagegen`；导演阶段默认只写资产职责和规格。

不要为了显得完整一次加载全部下游实现资料。

## 工作流

### 1. 固定声音与字幕版本

记录逐字稿、最终音频、主字幕、对齐字幕的路径、版本、时长和 hash。逐镜 cue、时间码和后续数字人必须引用同一条最终音频时间轴。

如果文稿仍有占位符、未核实数字、互相矛盾的段落、明显断句，或音频与字幕版本不一致，先触发职责门禁，不用画面掩盖上游问题。

### 2. 做导演诊断，不急着切镜头

先确定：

- 观众看完只记住什么；
- 核心承诺和最强证据；
- 短视频中，上游钩子的准确 cue、主承诺、首次有效兑现和最终兑现；
- 情绪起点、峰值和落点；
- 内容形态：真人主导 / 证据演示 / 动效隐喻 / 混合；
- 哪些内容是外部事实、片中实演、作者既往经验或编辑判断，以及各自需要多强的证明；
- 最可能让成片沦为 PPT 的原因。

这里只决定表达策略，不重排逐字稿。

### 3. 必要时先过导演方向门

当视觉方向尚未锁定、用户会“看了才知道”、或后续要投入完整制作时，按 `references/director-treatment.md` 给出 2–3 个真正不同的方向卡，并推荐一个。差异必须来自叙事载体、视觉世界、证据方式或节奏，不是换配色。

此时停在方向确认，不提前写完整分镜、生成资产或实现代码。YOLO 只能来自用户对当前任务的明确委托授权；“完整做完”或一般落盘请求不等于 YOLO，Agent 不得自行开启。授权后可以代为选择，但必须记录 `approval_mode: yolo` 与指向用户原始授权的 `approval_provenance`，并写明选择、淘汰理由和授权范围。

轻量真人剪辑、用户已经锁定视觉方向、或只要快速 B-roll 建议时，说明沿用方向后直接进入下一步，不强行制造选项。

### 4. 锁导演契约

方向确定后，建立：

- 一句话观看记忆；
- 视觉命题，以及动效主导内容的 Motion Thesis；
- 一个贯穿物或稳定视觉关系；
- 已锁定的背景 / 舞台母版，以及主体、证据层、留白和明暗对比如何与它共存；
- 从原稿名词、动词、数字和证据得到的视觉词典；
- 真实证据与抽象隐喻的分工；
- 与片中承诺成比例的证据等级；作者既往经验可以明确归因，不得伪造为本次实演；
- 1–4 个确实会复用的视觉/运动原语（包括 deliberate stillness）；不为凑数量新增原语；
- 一个明确的 AI 味动效禁用清单；
- 节奏曲线、镜头/空间策略、文字角色和声音策略；
- 禁用清单与 Anti-PPT 风险。

不是所有片子都需要强隐喻。真人或证据主导的视频可以用“证据逐步兑现”作为视觉命题，但仍要有统一的注意力路径和转场逻辑。

短视频、平台分发型视频或用户明确要求留存/传播时，同时按 `references/short-video-retention-directing.md` 锁定“短视频留存契约”。契约只提取已有稿件的钩子和兑现链；无法闭环时返回上游，不暗改旁白。

### 5. 写 Beat Graph

按语义、观众问题和字幕真实时间切 beat，不按句号机械切镜。每个 beat 使用 `references/beat-graph.md`，并引用对齐字幕中的真实起止时间，至少写清：

- 叙事任务和观众此刻的问题；
- 具体主承载物，不接受“流程图、数据、案例”等类别词冒充主角；
- 开始状态、结束状态和发生的事件；
- 运动动词或明确的静止理由；
- `motion` beat 的一个主运动原语、最多一个辅助运动；`readable-hold` 写明无主/辅运动及静止理由；两者都写重要内容何时可读；
- 镜头/图层运动与阅读停留；
- 证明类型与资产：真实实演、权威来源、作者归因陈述、编辑判断或无需证明；
- 短视频中，当前 beat 如何履行主承诺（提出 / 关联 / 部分兑现 / 加码或转折 / 完整兑现）；无关 beat 不强行标记；
- 如何把注意力交给下一 beat；
- 运动删除测试、重要转场中点和 AI 味拒绝条件；
- PPT 风险和失败条件。

动效主导视频也不设全片运动比例。每个标为 `motion` 的 beat 必须有超越淡入/滑入的可见语义变化；需要阅读、证据核对或缓冲的段落直接标为 `readable-hold` 并写静止理由。不为达到百分比把静止段改成装饰动画。

### 6. 只定义素材职责，不提前整理素材

导演稿阶段只定义每个 beat 需要什么证据、录屏、截图、B-roll、仿真 UI、图形或生图，以及失败退路。不要在导演稿确认前下载、生成、复制或归档正式素材，也不要让库存反向决定镜头。

导演稿确认、制作规格锁定后，再由导演规划者生成 `work/素材计划.md`；实际整理、获取和归档由已选管线的单一执行者完成。

### 7. 过导演质量门

短视频先按 `references/short-video-retention-directing.md` 过“留存导演门”，检查第一眼、首次兑现、中段递进和结尾收束；根因在稿件时返回上游。所有视频再按 `references/anti-ppt-gate.md` 检查：

- 全片是否像同一个世界，而不是一组独立页面；
- beat 是否发生状态变化或提供真实证明；
- 转场是否由对象、方向、镜头、声音或因果承接；
- 是否用一个主运动表达状态变化，并在重要内容落位后停稳；
- 去掉运动后是否损失含义、注意力路径或情绪；
- 是否命中重复上移淡入、统一漂浮呼吸、无锚装饰线、通用 AI 图标/粒子或空白淡出重启；
- 联系表不读字幕时是否仍能看出推进；
- 是否用大字、卡片或素材库存掩盖没有导演决定。

不通过就先改导演契约或 beat graph，不把问题推给实现端。

### 8. 用户确认导演稿后进入制作规格

导演稿必须先交给用户确认。用户准备继续制作时，再补 `references/production-spec.md` 的组件、内容、状态、真实时间和验收规格。

- 正式口播管线不提供“声音未锁定的制作规格”分支；缺少最终声音或字幕时返回第 1 步。
- HyperFrames 管线先检查当前项目已验证的 composition、`DESIGN.md` 与模板固定层，再按 `references/production-spec.md` 的准入顺序逐项标记 `reuse / adapt / create`。候选组件只是候选池，不得因为库存存在而反向决定镜头。
- 使用 Studio 暖白模板时，先按 `references/production-spec.md` 写“背景与舞台母版”规格并引用高清参考图；逐镜布局、内容明暗、底部字幕避让和大留白都必须在这个背景上成立。
- 每个 `motion` beat 必须按制作规格写状态变化、主/辅运动、可读锁定、接力、删除测试、拒绝条件和验收帧。重复使用的组件只在它本身发生语义状态变化时写动效契约；纯容器、阅读底板和静态证据不为了“组件完整”强行动。`进场/持续/强调/退出` 不能替代这些导演决定。
- HyperFrames 制作规格必须以 `references/hyperframes-motion-contract.template.json` 为结构生成 `work/motion-contract.json`，不得只在 Markdown 表格里写自由文本。外部 Remotion 管线可继续使用 `references/remotion-motion-contract.template.json`。
- 下游管线只负责翻译导演契约，不重新发明视觉世界。

## 交付

- 方向尚未确认时，只交付紧凑方向卡和推荐，不伪装成最终视频脚本。
- 方向已确认时，使用 `references/output-template.md`，删除不适用章节和空表。
- 同一决定只在一个章节完整定义，其他位置用 ID 引用；不要在导演诊断、契约、视觉词典、证据系统、素材职责和检查表中反复改写同一事实。
- 视觉词典只收录会跨 beat 复用或决定画面世界的核心翻译；证据系统只收录影响核心承诺的实质性主张；检查结果只写结论、例外和待办。
- 用户要求落盘时，默认保存为 `<VIDEO_WORKSPACE>/{project-slug}/视频脚本.md`。
- 默认不创建实现代码；用户确认导演稿且继续制作时才另建 `work/制作规格.md` 和 `work/素材计划.md`。只有两者锁定后才允许下游工单。

## 完成检查

- 已固定同一版逐字稿、完整音频和对齐字幕，没有暗中改写、重排或混用时间轴。
- 短视频已提取上游钩子与主承诺，镜头对第一眼、首次有效兑现、递进和最终收束都有明确决定；不能闭环的稿件已返回上游。
- 有一句清楚的观看记忆和视觉命题；动效主导内容有 Motion Thesis。
- 贯穿物、证据系统、视觉词典和运动语法来自本片内容，不是通用素材包。
- 每个 beat 有具体主承载物、起止状态、事件和下一 beat 的承接。
- 外部事实与片中实演有相称证据；作者既往经验被清楚归因，没有被伪造成现场证明，也没有无故阻塞制作。
- Anti-PPT gate 已在实现前通过。
- AI 味动效硬拒绝项为零；重要转场已有中点验收帧。
- 未指定工具时没有管线专属术语或隐性默认工具。
- 导演阶段只写素材职责；素材库存检查、获取和整理发生在导演稿与制作规格锁定之后。
- 每个 beat 的精确时间只来自锁定后的最终声音和字幕。
- 已选代码动画管线的制作规格已记录组件 `reuse / adapt / create` 决策，没有拿现成组件凑镜头。
- HyperFrames 的 `work/motion-contract.json` 已生成并通过 `hyperframes-scene-animator/scripts/validate_motion_contract.mjs`。
- 已锁定模板或背景时，导演契约和制作规格都记录了参考图、固定层与内容关系，没有把背景留给实现端临场决定。
- YOLO 若启用，已保存用户明确委托的 approval mode、provenance 和授权范围，没有根据文件存在自动推断用户已确认。
