# 技能级经验库（lessons-learned）

这是 video-script 跨项目的经验沉淀。两个来源喂进来：

1. **平台「作品表现」整改意见**——泊舟视频发布后，小红书/视频号/抖音给的真实反馈。
2. **项目级经验上提**——各视频工程 `{project}/work/lessons/LESSONS.md` 里，凡是「适用于未来项目」的经验，提炼一句上提到这里。

> **重要：沉淀前先看原视频是什么样子，别照抄平台原话。** 平台的反馈是结果，不是诊断。同一句「背景不好」，在深色故事片和暖白讲解片里意思完全相反。必须先搞清这条视频讲的啥、画面是什么调性、平台具体在指哪一段，再决定要不要写进规则、写成什么样。

## 这个文件怎么用

- **写脚本前必读**：在「内容诊断」和「选择画面系统」两步，对照下面的「核心经验」逐项匹配，别让上一条视频的毛病重演。
- **写完自检**：脚本的「制作检查清单」要把这里的相关项勾一遍。
- **拿到新反馈/项目经验就更新**：按文末「怎么更新」沉淀，先核对原视频实际情况再落规则。
- **按片匹配，不全量套用**：先看本片内容、调性和制作条件，只调用命中的经验。经验库越积越多，脚本反而要越会取舍。

## 核心经验

下面每条都标了**它从哪条真实视频来**、以及**为什么这么判断**（不是平台原话直译）。

### L1. 该具象的地方别只用抽象——给真实/仿真界面，不要光靠隐喻和关键词
这是三条视频被批评的同一个根，属于高频风险。

- **客服 Agent**（深色故事版）：用「墨·纸·朱砂」抽象隐喻 + 极简终端框讲 demo、退款、查库存。平台要的是「模拟界面截图 / 动态效果，让抽象技术问题直观」。
- **Vibe Coding**（暖白 Studio 版）：voiceover-only，主画面只放关键词，素材里录屏 `[]`、截图 `[]` 全空。平台要的是「AI 对话界面录屏、代码运行效果展示」。
- **AI 视频制作心法**（暖白口播版）：已经有流程卡和示意动画，但「声音克隆、字幕文件」等关键步骤仍以卡片解释为主。平台建议把可操作步骤做成动态演示，让教学更直观。

→ **规则**：凡讲到**能截图 / 能录屏**的具体东西（产品操作、AI 对话、代码在跑、报错弹窗），分镜要给真实或仿真的界面画面，标「需真实/仿真 UI 或录屏」，别只用一颗隐喻球或一行关键词大字代过去。

⚠️ **这不是要砍掉抽象设计系统。** 客服 Agent 的发光球/朱砂配色是对的记忆锚点，要留。问题是「该具象的地方也抽象了」——抽象做骨架、具象做证据，两者搭配，不是二选一。

### L2. 一种版式 / 一种底色别从头铺到尾——画面要跟理解状态一起演进
三条都被说「单调 / 让画面动起来」，属于高频风险。Vibe Coding 6 个章节共用一套 Studio 版式；客服 Agent 长段维持同一种深色；AI 视频制作心法虽然有不少动效，但长期仍是暖白底 + 卡片，画面语法变化不够可感。

→ **规则**：新段落发生新问题、新证据或新关系时，画面状态也要能让观众感知这个变化；可以通过真实证据、对象状态、构图、景别、明暗或有理由的静止完成。不按段落计时器强制换背景、加图标或加动画。只有当语义已变而画面仍无法反映时，才标记为未演进。

### L3. 明暗不是问题，「一种调子到底」才是
**关键反例**：客服 Agent 被嫌**太暗压抑**，Vibe Coding 被嫌**太白单调**——方向相反。所以别写「背景要亮一点」这种规则，那会把深色片带沟里。真正的问题是层次、证据和情绪节点没有产生可感的对比，不是前景元素没有循环动。

→ **规则**：
- 深色故事片：在情绪点 / 关键节点通过明度、色温、景别或证据面板建立对比，别一暗到底。若需要动态光影，必须对应明确情绪或叙事事件。
- 浅色讲解片：用真实素材、深色证据面板、层级与留白对比，别一白到底。只有很淡的背景纹理仍可能被感知成纯白 PPT 底；层次要让普通观看状态下看得见，但不能抢内容。

### L4. 大段落切换要有可感知的视觉接力，不默认靠标题卡
Vibe Coding 平台建议用「正确姿势」这类标题卡引出下一部分。客服 Agent 的三幕章节卡也有效；但标题卡只是手段之一，连续使用仍可能形成“换 PPT 页”的感觉。

→ **规则**：节奏结构里每个大段落的切换点必须有可感知接力——优先让上一段的对象、方向、镜头、声音或未回答问题进入下一段；标题卡只在确实需要章节停顿和重新定向时使用，不能成为默认分段模板。

### L5. 关键概念要重点强调
Vibe Coding 的 MVP、compound，以及 AI 视频制作心法的「字幕文件」「三条铁律」，都被平台建议用更大字号、不同颜色或强调动画拉开信息权重。

→ **规则**：关键概念必须有明确的信息层级，可以由字号、色彩、位置、停留、证据对应或语义动作承担；不要为了“强调”默认加一次放大/缩小。

### L6. 情绪点要有画面反应——但配料方式要服从片子调性
客服 Agent 平台建议「AI 出 bug 时配有趣动画 / 表情包」。

→ **规则**：翻车 / 出错 / 惊讶的点，画面要给反应，别平铺。
⚠️ **但要看调性**：客服 Agent 是严肃紧张的叙事片，硬塞表情包会串味。这种片的情绪起伏靠**音乐重拍、景别急推、红色资金流冲击、震屏**来做，效果和「表情包」一个目的，但不破坏质感。表情包式配料更适合轻松吐槽类视频。平台给的是方向（情绪要有反应），不是必须照搬的手法。

### L7. 丰富度来自理解的变化，不是字数或动画类型数（高频）
这是一对镜像坑：早期版本把逐字稿大量贴上主画面；后来又把“动画太少”误读成每个元素都要进场、持续、强调和退出，结果变成重复淡入、漂浮呼吸和卡片编舞。两者都没有让观众多明白一件事。

→ **规则**：文字宁少勿多（一屏原则上 ≤5 个独立文字元素，可以无字）。每个 beat 先写观众理解的状态 A→B，再选择真实 UI、证据、图示、数据、镜头或完全静止的阅读帧。一个主运动、最多一个辅助运动；事件完成后必须留足可读时间。静止是合法的，没有语义变化的循环不合格。

### L8. 文字描述的分镜下游 AI 无法忠实还原——必须附「制作还原规格」
来自 J-space 视频（2026-07）第一版 Remotion 实现。分镜表写"仿真 Claude 对话 UI（需真实产品感）""细线稿鹦鹉""词块辉光亮起"，全是给人看的形容；下游 AI 实现成：空白白框当对话 UI、一张静态词块总表从头用到尾（第 58s 就剧透了后面三个实验的答案词）、鹦鹉画成看不出是什么的墨团、示意动画退化成关键词卡、多处整屏空白。**根因不是实现方不认真，是脚本没给可执行规格——凡是留给自由发挥的地方，产出就不可控。**

→ **规则**：交给动画/代码管线（HyperFrames/Remotion）的脚本，必须按 `references/production-spec.md` 附 `work/制作规格.md`：组件规格（色值/结构/状态）、逐镜状态表（字幕行号 cue → 变化；概念元素防剧透、主角元素镜内事件）、仿真内容逐条文本、图形绘制配方（具象图形禁徒手发挥：几何配方/现成矢量/经典轮廓+退路 三选一）、空屏骨架规则、抽帧验收清单。分镜表每个「⏳ 待生成」在规格里必须有对应条目。

### L9. 复用是手段不是目标——先定画面，再查库存
来自 J-space 视频（2026-07），与 L8 同一版 proof。资产库指引"能复用就复用"被执行成义务：推导链路径线稿等现成组件在不合适的镜头也被硬塞进画面——组件确实"用上了"，但既不表意也不好看，观众只看到几条莫名其妙的线。同样的偏差也出现在实现端：制作方倾向复用已建好的组件皮肤而不是为该镜新做更贴的画面。

→ **规则**：设计每一镜时先回答"最能讲清这句话的画面是什么"，画面定了才查库存。判断口径：**假如库里没有这个资产，你还会设计出同样的画面吗？不会，就不要用它。** 宁可多标一项 ⏳ 待生成，也不为消化库存凑画面。实现端同理：规格里写了新组件就新做，不许拿现成组件"凑合替代"。

### L10. Studio 暖白蓝金镜像透视网格是当前固定舞台——无 PIP 不等于换背景

来自 J-space 参考帧与后续模板校正（2026-07）。历史版本先把背景退化成普通白底/1px 平面网格，又一度误写成乳白瓦楞玻璃，两者都与已锁定参考图不一致。

→ **规则**：凡使用 `talking-head-hyperframes` 的 Studio 管线，默认直接继承脚手架已验证的固定舞台：暖白画布、蓝/暖金 wash、上下独立投影的镜像透视格、horizon、中央 veil 和克制 grain。不凭截图重画，不恢复全宽横线、平面 CSS 网格、瓦楞玻璃、网页 shell 或漂浮光斑。PIP 是可选且默认静态的前景层；删除 PIP 不改变背景。字幕固定层保留，顶部栏与内容卡不是模板固定层。只有用户明确确认新主题时才替换。

## 来源案例库

> 每条记：视频名 + 对应 `视频工程/` 项目 + 实际调性 + 平台反馈 + 落到哪条经验。

### 案例 1 ｜客服 Agent 的上线噩梦
- **项目**：`视频工程/prompt-context-harness/`（逐字稿·分镜·配音）→ `视频工程/harness-agent/`（成片）
- **实际调性**：「墨·纸·朱砂·故事版」，刻意调暗、紧张的叙事氛围；7 分 14 秒、37 场景、纯叙事无术语标注；讲一个工程师阿白做 AI 客服 Agent 从 Demo 完美到上线翻车的故事（Prompt → Context → Harness 三次撞墙）。画面以抽象隐喻（发光核心球 + 极简终端框 + 资金流光束）为主。
- **平台**：小红书 ·「作品表现」· 2026-06-29
- **原话**：①提升视觉丰富度——AI 出 bug 配有趣动画/表情包让情绪起伏；关键情节（自动退款）插模拟界面截图或动态效果让抽象问题直观。②优化画面质感——背景偏暗显压抑，换更明亮简洁或科技感动态背景。
- **落点**：L1（自动退款该有仿真 UI）、L3（深色片要在情绪点提亮，而非整体调亮）、L6（出 bug 要情绪反应，但用音乐/景别而非表情包，保叙事质感）。

### 案例 2 ｜Vibe Coding 入门
- **项目**：`视频工程/vibe-coding-intro/`
- **实际调性**：「墨·纸·朱砂」的暖白 Studio 版；voiceover-only 讲解片，暖白画布 `#f4f4f1` + 黑灰大字 + 克制蓝点缀；6 章（认识/定义/协作/误区/流程/决策）讲 Vibe Coding 是什么、AI 编程工作流（Brainstorm→Doc→Plan→Work→Review→Compound）。主画面只放关键词，明确不用录屏和截图。
- **平台**：视频号 ·「作品表现」· 2026-06-29
- **原话**：①丰富画面元素——全程白底黑字单调，穿插 AI 对话录屏、代码运行展示；不同步骤换背景图或配图标（如「沉淀」配文件夹图标）。②优化信息节奏——用文字卡片/转场划分段落（讲完「许愿式编程」用「正确姿势」标题卡引出下一段）；关键概念（MVP、compound）放大或变色强调。
- **落点**：L1（缺录屏/代码展示）、L2（6 章一套版式太单调，每步要换画面）、L3（暖白片要加动态层次）、L4（标题卡分段）、L5（关键概念强调）。
- **印证**：该项目 `work/lessons/LESSONS.md` 早有一条同向经验——「抽象方块 + 长时间静止画面会让讲解片貌合神离，画面要具象、每个元素挂字幕时间戳逐句点亮」，与 L1/L2 一致，互相印证。

- **项目**：`视频工程/j-space-explained/`
- **实际调性**：Studio 暖白讲解片（talking-head-remotion 模板，16:9 无人出镜），27 镜；核心组件是"仿真 Claude 对话 UI + J-space 深色监视面板"双栏。
- **来源**：非平台反馈——用户看第一版预览（`renders/preview-low.mp4`）后反馈"很多东西特别不形象，没办法形象地描述出视频内容"。抽帧审查（`work/review/frames/`）确认是脚本→实现落差，整改依据在 `work/组件规格与整改清单.md`。
- **落点**：L8（新增）、L9（新增，现成组件硬塞不合适的镜头）；同时再次印证 L1（对话 UI/邮件做成空框裸文字）和 L7 镜像坑（示意动画退化成关键词卡）。

### 案例 4 ｜AI 做视频的心法
- **项目**：`视频工程/ai-video-mindset/`
- **实际调性**：6 分 35 秒横屏露脸讲解；暖白底 + 顶部章节进度 + 右下 PIP，主体以流程节点、清单卡和示意动画讲「声音优先、字幕文件、三条铁律」。抽帧可见背景有细纹，但整体长期维持同一浅色卡片系统。
- **平台**：作品表现反馈 · 2026-07-10。播放量 7,125、较往期上涨 159.56%；平台称“可能”与平均播放时长上升、2 秒跳出率下降有关，这是归因提示，不是已证实因果。
- **正向信号**：内容价值和声音优先的方法得到明确肯定；本次不因画面建议推翻叙事与声音主线。
- **优化建议**：关键步骤用动态演示；背景增加可感知层次；「字幕文件」「三条铁律」强化视觉权重；「先写稿再配音」用箭头和图标组成简单流程图。
- **落点**：再次印证 L1/L2/L3/L5/L7；不新增重复规则。

## 怎么更新

下次有视频拿到平台「作品表现」整改意见、或某个项目 `work/lessons/LESSONS.md` 攒了通用经验时：

1. **先还原现场**：打开对应 `视频工程/{project}/` 看逐字稿、分镜/DESIGN、成片截图，搞清这条视频讲什么、什么调性、平台具体指哪一段。别跳过这步直接抄反馈。
2. **拆开事实和判断**：播放量、时长、跳出率是事实；平台写的「可能因为」是推测；整改项是建议。三者分开记，不把相关性升级成因果。
3. **在「来源案例库」追加一条**：视频名、项目路径、实际调性、数据/反馈摘要、正向信号、落到哪条经验。保留能帮助以后判断的上下文，不整段复制平台话术。
4. **核对「核心经验」**：
   - 命中已有经验 → 在那条下补一句印证（说明又踩一次 = 高频坑，要重点盯）。
   - 是新坑 → 新增一条，写清「来自哪条视频 / 为什么这么判断 / → 分镜哪一步落地」，并标注调性适用边界（像 L6 那样，别让一个手法被无差别套到所有片子）。
5. **定期合并**：多条反馈本质相同就合并到一条共性规则，只在案例库保留来源；不要为每条平台话术新建一条经验。反复命中的经验标「高频」，写脚本时优先排查。
