# AI 技术口播剪辑方法论

这份 reference 从影视飓风 Tim 的剪映系统课中提炼，只保留对泊舟 AI/技术类视频最有用的部分。它不是剪映按钮教程，而是“逐字稿如何变成可制作视频”的判断框架。

## 四条底层原则

### 1. 信息密度决定镜头节奏

镜头时长不是凭感觉决定，而是由观众需要吸收的信息量决定。

- 信息少：一个情绪点、一个关键词、一个转场，可快切。
- 信息中：一个概念、一个类比、一个例子，要给稳定画面。
- 信息高：多层关系、参数对比、步骤流程，要停久一点，并用图形拆层。

技术科普最常见的问题是：旁白密度高，画面却切得太快。观众还没看懂图，下一张已经来了。

### 2. 踩梯子保护观众预期

每一段都要让观众对下一段有期待，下一段又满足并推进这个期待。

例子：

```text
大模型只会预测下一个 token
-> 那它怎么读懂文字？
-> 靠 token
-> 那它怎么记住聊天历史？
-> 靠 context
-> 那资料太多怎么办？
-> 靠 RAG
```

这就是技术解释里的“踩梯子”。为了保护这个递进关系，可以减少转场、减少音乐、减少无关装饰。观众要看的不是特效，而是“下一步怎么解释”。

### 3. 消除剪辑痕迹

剪辑的目标不是让观众意识到“这里剪得很花”，而是让信息自然流过去。

可用手法：

- B-roll 遮蔽口播硬切和气口。
- J-cut：声音先出现，画面后进入，提前制造心理预期。
- L-cut：画面切走，声音延续，减少断裂感。
- 环境音和点击音让 UI 演示更真实。
- 音乐尾迹、淡入淡出和短 hit 处理段落边界。

### 4. 工具是调味料，思维是主菜

关键帧、变速、抠像、跟踪、调色、特效都只是工具。技术视频最重要的是：画面是否帮助观众更快理解。

使用工具前先问：

- 这个动效是强调信息，还是只是显得忙？
- 这个转场是否打断观众正在爬的梯子？
- 这个 B-roll 是否补充说明，还是只是填空？
- 这个花字是否抓住关键词，还是在复读整句字幕？

## 适合 AI 技术视频的手法

### 口播精剪 + A/B-roll 协同

A-roll 是口播主线，B-roll 是解释层。先把 A-roll 剪成清晰叙事骨架，再往上叠 B-roll。

B-roll 的五条规则：

1. 覆盖口播硬切点，不能让气口剪辑裸露。
2. 对齐口播语义，不能“漏字”：画面结束时，这句话还没说完会跳出理解。
3. 成组添加，同一信息最好有多景别或多状态。
4. 不重复使用同一个画面，除非刻意形成回环。
5. 准备万能 B-roll：终端、代码 diff、浏览器、AI 对话、GitHub、产品页面、笔记、流程图、抽象节点动画。

双时间线筛选法可以转成脚本规则：先建立 B-roll 候选池，再逐段根据口播语义“捞素材”，不要临时逐个搜索。

### 文字包装

技术口播里的文字不是字幕复读，而是视觉锚点。

适合大字/花字的内容：

- 新概念第一次出现。
- 反差判断。
- 三步法、三句话、清单。
- 数据、价格、参数、时间。
- 错误做法和危险提醒。

文字规范：

- 用加粗、边缘平滑的非衬线字体。
- 核心信息大，辅助信息小。
- 同屏文字不要和脸、字幕、关键 UI 抢位置。
- 动态画面里的文字要稳定可读，别追求复杂字体。

可迁移包装：

- 抠像三明治：人物前景 + 背后关键词 + 背景，用于强调术语。
- 数字滚动：参数、价格、倒计时、版本变化。
- 蒙版窗口：只露出关键变化区域。
- 侧边标签：给 UI、代码、流程节点命名。

### 节奏、景别和蒙太奇

没有口播主线的片头、转场或小混剪，可以用：

- 景别递进：远景建立环境，中景给关系，特写落到细节。
- 匹配剪辑：用相似形状、运动轨迹或 UI 结构衔接。
- 库里肖夫效应：把两个无直接关系的画面并置，让观众脑补关联。

技术视频中不要滥用纯混剪。它适合开头预告、章节转场、结尾回顾，不适合承载复杂解释。

### 关键帧和变速

关键帧让静态画面有注意力路径。

常用：

- 局部放大代码或 UI。
- 镜头缓慢推近一个概念卡。
- 箭头沿流程移动。
- 节点依次亮起。
- 错误路径变红，正确路径变亮。

注意：

- 缩放和位置要同步，否则画面会机械。
- 曲线缓动比线性运动自然。
- 高密度信息不要一直动，观众需要读。

变速主要用于 B-roll 或片头，不是技术解释的主工具。用来制造动能、转场或动作反差即可。

### 声音设计

声音是剪辑的一部分，不是最后铺背景音乐。

技术视频可用：

- 鼠标点击音、键盘音：增强录屏真实感。
- whoosh：卡片/流程切换。
- hit：危险、结论、反差。
- rise：进入一个重要节点前的期待。
- 低频停顿：错误、风险、系统崩溃。
- 环境音：办公室、终端、风扇、通知声，但要少量。

J-cut 用法：画面还没切到 GitHub，先听到点击/通知；还没出现警示卡，先有低频 hit。

L-cut 用法：画面切到流程图，但上一句口播的声音自然延续，不让剪点太硬。

### 音效从哪来：找现成优先，少用 AI 生成

原则：能找现成的，就不要 AI 生成。技术口播里 90% 是功能性音效（点击、whoosh、叮、键盘、上升、错误音），这些是高度标准化的声音，现成的又快、又稳、又对耳朵；AI 生成这类反而不稳定、容易出怪声。

按优先级：

1. 剪映自带音效库（首选）：左上角音频工具往下滑「音效素材」，搜中文关键词即可，覆盖日常 80% 需求，免费零下载。
2. 专门音效站（要更独特时）：耳聆网、淘声网、爱给网、Freesound、Pixabay 音效、YouTube Audio Library。
3. AI 生成（只在找不到现成时）：需要很具体、找不到的场景氛围音（如「AI 数据中心嗡嗡运转 + 电流脉冲」），或想做标志性个人音效时，才使用当前工作区已安装的声音/音效生成能力。日常切片用不上。

AI 技术口播可候选音效 → 剪映搜索词速查。这些不得“直接照填”：只有画面存在按钮、回车、数字变化、错误或节点建立等真实事件，且删除声音会损失节奏/因果时，才在素材计划中记录。普通切画面、换卡片或关键词出现不自动配 whoosh/ding。

| 场景 | 搜索词 | 放置时机 |
|---|---|---|
| 点按钮 / 终端回车 | 点击、回车、打字 | 对齐动作那一帧 |
| 切画面 / 换卡片 | whoosh、转场、嗖 | 切点前 2-3 帧起 |
| 强调关键词 / 上大字 | 叮、弹出、ding、上升 | 大字出现同帧，或早 1-2 帧（J-cut）|
| 数字跳动 / 参数对比 | 计数、滚动、哒哒 | 跟随数字变化 |
| 报错 / 风险提醒 | 错误、警告、低频、嗡 | 警示卡出现前给一个 hit |
| 进入重要节点 | rise、上升、蓄力 | 节点前 0.5-1 秒铺 |

## 结构方法

### 短视频

短视频的停滑、承诺—兑现链、注意力重置和结尾回收由 `short-video-retention-directing.md` 单一维护。本文件只补充信息密度、踩梯子、声画剪辑和节奏判断，不再复制一套短视频时间公式。

### 3-7 分钟技术口播

适合新手扫盲、观点解释、工具介绍：

```text
开头：痛点 + 承诺
第一段：建立总线
第二段：解释核心概念
第三段：给例子或演示
第四段：提醒误区/边界
结尾：总结公式 + 下一步
```

### 7-15 分钟长讲解

用时钟理论检查：

- 0 点：强钩子。
- 3 点：第一个明确收获或案例。
- 6 点：中段波峰，给最有价值的解释、演示或反差。
- 9 点：加速收束，给总结和迁移。

长视频不要从头到尾保持同一节奏。要有波峰和缓冲，但后段通常不要比前段更慢。

## HyperFrames 转译规则

把剪辑手法转成 HTML 视频设计时，不要只说“加动效”，要写成可实现的状态变化。

示例：

```text
画面任务：解释 context window
布局：左侧一张桌子，右侧不断堆入资料卡片
动效：资料卡片从右侧进入，桌面接近边界时出现红色容量线
花字：上下文窗口 = 这次能摊开的资料桌面
音效：卡片落下轻 click，容量线出现时短 hit
```

设计时优先说明：

- 场景最终可见布局。
- 哪些元素先出现，哪些后出现。
- 哪个元素是观众视线中心。
- 转场代表什么关系。
- 文本是否可能越界。

HyperFrames 制作阶段再关心具体 `data-duration`、GSAP 和 CSS。脚本阶段先把“该做什么画面”和“为什么这样做”说清楚。

## 低优先级内容

这些课程内容对当前 AI 技术口播不是优先：

- 平面跟踪：除非有实拍物体、桌面、屏幕透视贴字。
- 多机位采访：除非做访谈、对谈、播客视频。
- 复杂调色：先保证画面干净统一即可。
- 导出参数：属于制作交付流程，不是脚本设计核心。

## 最终检查

一份好的视频脚本应该能回答：

- 逐字稿哪里信息密度最高？
- 观众每一段为什么继续看？
- 哪些画面必须用 B-roll，哪些可以露脸讲？
- 哪些概念需要图形化？
- 哪些地方用声音提前带入？
- 哪些效果只是装饰，可以删掉？
- HyperFrames 制作人拿到后是否知道要做哪些场景和组件？
