# Beat Graph

Beat Graph 把锁定后的导演契约变成连续时间线。它不是逐句配图表，也不是组件工单。

## 1. 切分原则

一个 beat 对应一个观众任务或一次可感知变化。以下任一变化通常意味着新 beat：

- 观众的问题改变；
- 证明方式改变；
- 主承载物发生关键状态变化；
- 情绪、尺度、视角或节奏发生转折；
- 注意力被明确交给新的对象。

不要按句号机械切镜。相邻句共同完成一次证明时应留在同一 beat；一句话内部发生明显“之前→之后”时也可能需要两个 beat。

## 2. 每个 Beat 的必填字段

| 字段 | 要回答的问题 |
|---|---|
| `beat_id / cue` | 对应哪段准确原文或相对位置？ |
| 叙事任务 | hook / establish / mechanism / proof / contrast / consequence / risk / release / close 中承担什么？ |
| 观众问题 | 观众此刻在等什么答案？ |
| 留存 / 承诺状态（短视频按需） | 这一 beat 对 `P01/P02` 是提出、关联、部分兑现、加码/转折还是完整兑现？无关时写无或省略。 |
| 主承载物 | 谁或什么承担这一 beat？必须具体到对象、人物、界面或关系。 |
| 开始状态 | 进入 beat 时，主承载物已经是什么状态？ |
| 结束状态 | 离开 beat 时，观众看见它变成什么状态？ |
| 事件 / 运动动词 | draw、route、type、lock、split、compare、scan、collapse、hand off，或为什么必须静止？ |
| 主运动 / 辅助运动 | `motion` 中哪一个运动真正改变理解；是否需要最多一个气氛、聚焦或承接用辅助运动？`readable-hold` 两项都写无。 |
| 镜头 / 图层 | 视角如何移动；前中后景如何分工？ |
| 文字角色 | 标题、标签、数字、字幕、CTA 或无；不能让长文承担主要解释。 |
| 证明类型 / 资产 | 本段是片中实演、外部事实、作者既往经验、编辑判断还是无需证明？引用哪个 `E##` 或资产；不要把归因陈述伪造成实演。 |
| 阅读锁定与声音 | 何时运动、何时停稳供阅读，声音如何提前或延续注意力？ |
| 下一 beat 接力 / 转场中点 | 哪个对象、方向、动作、声音或未回答问题把注意力交出去；中点帧看见什么？ |
| 删除测试 / 拒绝条件 | 删除运动损失什么；这一 beat 最可能退化成哪种 PPT 或 AI 味动效？ |

## 3. 主承载物标准

不合格：

- `流程图`
- `数据可视化`
- `案例画面`
- `科技感卡片`
- `仿真 UI`

合格：

- `从参考音频进入推理节点的同一条蓝色波形`
- `左侧保持不变的文本输入框与右侧逐步生成的音频轨`
- `从“待处理”变成“已对齐”的字幕文件行`
- `同一个报错窗口在修复前后改变状态`

类别词只能说明形态，不能代替导演决定。

## 4. 状态变化标准

有效状态变化包括：

- 内容被输入、路由、组装、比较、验证、锁定或导出；
- 一个对象改变数量、关系、含义、位置、材质或权限状态；
- 镜头发现先前隐藏的信息；
- 真实证据从模糊、局部或未验证变成清楚、完整或已验证；
- 人物表情、动作或环境反应推进情绪。

以下不算主要状态变化：

- 整张卡片淡入后静止；
- 标题从下方滑入；
- 图标逐个 pop；
- 同一布局只换文字；
- 背景粒子一直漂但内容没有变化。

静止可以成立，但必须有理由：高密度证据留读、情绪停顿、结论落定或反差前的蓄力。写清静止持续多久以及它保护什么。

每个动效主导 beat 默认只有一个主运动原语、最多一个辅助运动。`进场/持续/强调/退出` 是实现生命周期，不替代状态变化；若主要动作只是统一 `opacity+y`、漂浮呼吸或装饰发光，该 beat 不通过。

## 5. 连续性与接力

相邻 beat 至少使用一种接力：

- **对象接力**：上一镜的波形、光标、文件、人物动作进入下一镜；
- **方向接力**：上一镜向右的运动由下一镜继续，而不是重置；
- **形状接力**：圆形波形节点变成录音按钮或进度节点；
- **镜头接力**：推进到局部、拉远发现系统、裁切进入新空间；
- **声音接力**：J-cut、L-cut、点击、呼吸或音乐尾迹提前/延续；
- **问题接力**：上一 beat 留下的真实问题由下一 beat 回答。

“切到下一页”“出现章节标题”“淡出再淡入”不算接力，除非停顿或断裂本身具有叙事意义。

重要转场必须指定中点帧。中点不能是意外空白、两场都不可读或纯特效糊屏；没有合理接力时，使用有理由的硬切或静止停顿。

## 6. 短视频留存分支

只在目标是短视频、平台分发型视频，或用户明确要求完播/留存/传播潜力时使用。按 `short-video-retention-directing.md` 先锁定主承诺，再对相关 beat 标记 `P01:状态`。

- 开头 beat 除了写 `hook`，还要说清 `0–2s` 第一眼目标、立即发生的语义事件，以及它如何与稿件钩子同义。
- “部分兑现”必须真正给出答案、结果、证据或可执行收获；“下面会告诉你”不算兑现。
- 注意力重置要改变观众的理解、证据或情绪状态，不按固定秒数添加与原稿无关的动效。
- 结尾 beat 要标明主承诺是否完整兑现，并用对象、问题、证据或反差回收开头；CTA 不能替代收束。
- 若已锁定逐字稿无法完成上述链路，引用准确 cue 标记上游阻塞，不在 Beat Graph 中新造台词或调换顺序。

## 7. 不同形态的分支

### 真人主导

- 人物是稳定锚点，B-roll 只在需要证明、遮切或改变注意力时进入。
- 不要求每句话都有新动画。
- 景别、眼神、手势、真实操作和声音也可以形成状态变化。

### 证据演示主导

- 真实界面和结果是主角，抽象图形只负责解释看不见的因果。
- 截图必须说明出现前后状态、裁切焦点和读图时间。
- 不用空白 UI 框或“此处放代码”占位。

### 作者经验与编辑判断

- 原稿中的“我试过、我发现、我的建议”先按作者归因处理，不自动升级为片中实验。
- 有历史素材就使用并标明时间/环境；没有素材可以用明确归因的文字、口播锚点或示意关系承载。
- 只有本片承诺现场验证时，缺少输入、环境或结果才构成制作阻塞。
- 示意画面不得伪装成真实截图或精确测量结果。

### 动效隐喻主导

- 不设“多少比例必须动”。标为 `motion` 的 beat 必须有超越淡入/滑入的语义状态变化；标为 `readable-hold` 的 beat 必须完全说清静止理由和阅读目标。
- 选择 1–4 个确实复用的视觉/运动原语（可包含 deliberate stillness）；不为凑数量新增原语。
- 每个隐喻都要能指回原稿，不做只负责漂亮的抽象运动。

### 混合形态

- 明确谁是骨架：人物、证据或贯穿物只能有一个主导者。
- 其他形态作为证明层或解释层，不轮流争夺主角。

## 8. Beat Graph 完成门

- 不读花字也能说出每个 beat 的主承载物和事件。
- 任意两个相邻 beat 都能指出接力关系。
- 没有连续三个 beat 使用相同布局、相同进场和相同节奏。
- 短视频的开头有与上游钩子同义的第一眼目标和语义事件，主承诺在真实 cue 中经过首次有效兑现并最终闭环。
- 短视频的注意力重置都带来新证据、反差、结果、尺度、视角、情绪或问题状态，没有为保留数据机械加运动。
- 每个动效主导 beat 有一个主运动、最多一个辅助运动和可读锁定。
- 影响核心承诺的外部事实和片中实演都有相称证据；作者经验与编辑判断被正确归因。
- 抽象隐喻没有替代真实界面、数字或结果。
- 运动删除测试至少会损失含义、注意力路径或情绪之一；否则删掉该运动。
- 重要转场中点可验收，且没有重复 `opacity+y`、统一漂浮呼吸、无锚装饰线、通用 AI 图标/粒子或空白淡出重启。
