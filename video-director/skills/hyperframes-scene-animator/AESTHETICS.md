# HyperFrames 导演与审美硬规格

这是验收标准，不是动效菜单。核心顺序是：**状态变化 → 注意力路径 → 可读停留 → 接力**。

## 1. 构图和信息

- 1920×1080 使用 8pt 网格；每帧一个明确焦点，两个并列对象可共同构成一个对比焦点。
- 留白原则上不少于 1/3；信息多就分阶段建立，不把完整字幕再复制上屏。
- 安全区服务当前 16:9 成片；只在制作规格明确需要竖版复用时才加中央裁切约束。
- 字幕区、PIP 和人脸不得被项目内容遮挡。
- 每帧独立文字元素原则上不超过 5 个；代码、数字、路径和英文标识使用 mono。不得使用 lorem 或占位文案。

## 2. 视觉体系

- 色彩使用项目 token；红=错误/危险，蓝=方案/选中，绿=通过/解锁，深色=终端/代码/黑区证据。
- 玻璃卡只在设计明确选用“玻璃”语言时才使用，且必须同时有半透明底、轻描边与受控模糊；不得把每个容器都做成玻璃卡。
- 阴影轻、软、有环境关系；禁用纯黑硬阴影。同类容器的圆角、描边、间距必须一致。
- 仿真 UI 必须有真实信息层级与足够的界面组件；空窗口、几何占位、只换配色的“不同版本”都不成立。

## 3. 语义动效

每写一个动作，先回答：“观众因此多明白了什么？”答不上来就删。

- 一个 `motion` beat 默认只有一个主运动，最多一个辅助运动。主运动用语义动词：揭示、输入、组装、比较、验证、压缩、变形、路由、锁定、交接等。`readable-hold` 的主/辅运动都为无。
- hero moment 不是每个场景的必填项。一个序列或重要转折可以有一个主角事件；阅读、证据或缓冲段可以没有。
- 次要元素可以用短 opacity、位移或 scale 完成技术性建立，但不得用同一套 `opacity+y+scale` 包装所有内容。
- 不强制所有运动使用同一 easing。一个项目选一个默认的快出缓停曲线，机械或扫描可 linear，物理落位可 spring；差异必须来自语义。
- 时长是可读性结果，不是硬套表格。快反馈、元素建立和场景级事件应有明显层级，具体时长由字幕 cue 与验收点确定。
- stagger 只表达顺序，不冒充状态变化。事件完成后，重要内容必须停稳供阅读。
- 不用“每 5–10 秒必须动一次”这类计时器代替节奏。节奏由 beat 与理解负荷决定；长时可读停留是合法的。
- 强调优先改变关系、对比、镜头或证据状态，不把抖动、bounce、短暂清空背景当作默认重音。
- 非叙事性离场可克制清理；承担转场的元素必须交给下一 beat，不得先把全屏淡空。

## 4. 持续动作白名单

默认只允许固定背景的低幅运动。以下内容默认静止：字幕、PIP、卡片、标题、代码、图标、证据、装饰线和光斑。

这是本项目对 HyperFrames 通用 house style 的显式覆盖：不因通用模板默认的环境光、CSS 装饰循环或场景漂移而扩大白名单。需要额外循环时，在对应 beat 的 `continuousMotions` 中结构化写明：对象、周期、振幅、开始/停止时间、语义作用和删除测试。默认是空数组；缺字段的循环必须拒绝，`repeat: -1` 在有限视频时间线中永远拒绝。

## 5. Anti-PPT / AI 味硬拒绝

命中任一项即打回：

- 连续镜头重复上移淡入、同形卡片只换标签，或每页先清空再重开；
- 所有元素一直漂浮、呼吸、发光，重要文字从不停稳；
- 用 sparkle、粒子、火箭、闪电、AI 芯片、随机勾号、霓虹 HUD 填空；
- 线、弧、轨道、扫描线或光带没有起点锚、终点锚和叙事任务；
- 转场中点是意外空白、两场都不可读或纯特效糊屏；
- 删除动作后只损失“更忙/更炫”，不损失理解、证明、注意力或情绪；
- 使用旧动效库中的呼吸、漂浮或 pop 默认，却没有在当前 beat 的契约中重新证明。

## 6. Cue、scene 和转场

- cue 是状态推进点，不是整张画面的出生点。开场可先有不剧透的空间、底图或等待态，但不得是空容器。
- 概念只能在所属 cue 建立；验收必须比较指定的前/后状态，不用任意时间点的元素数量代替语义证明。
- 每个真实 HyperFrames scene 必须有显式入口，并通过对象、方向、遮罩、镜头、声音或因果关系完成语义转场。
- `readable-hold` 是 beat，不等于新 scene。它可以在已经建立的 scene 内完全静止，保留当前可读状态。
- 同一 scene 内的连续 beat 不重播入口。非最终 scene 不做独立离场；出场是语义转场的一部分，转场开始前不得先把 outgoing scene 淡空。最终 scene 可以在成片结束处做克制离场。
- 转场中点必须是有意图的混合或交接状态，并在 acceptance snapshot 中写明应看到什么。
- 禁止通用全局 crossfade 或共享 `enterStyle`。scene 入口与转场必须逐场由语义证明，不能成为模板级视觉默认值。

## 7. HyperFrames 可见性和媒体边界

- 项目层适配禁止动画 `visibility`、`display` 和 `autoAlpha`。通用 GSAP 文档中对 `autoAlpha` 的建议不覆盖此约束。
- 显隐使用 `opacity`、`clipPath` 或 transform；`.clip` 和 timed composition 的生命周期始终交给 HyperFrames。
- 人像或 PIP 视频由 framework 控制播放和 `currentTime`，视觉位移、遮罩和缩放只作用于非 timed wrapper；不直接动画 `<video>`。
- 每个 composition 只有一个同步构建、`paused: true` 并注册到正确 composition id 的 master timeline。同一时间不允许多个 tween/timeline 竞争同一对象的同一属性。

## 8. 定帧与实看

静帧只验构图和状态，不能证明动效成立。交付前同时回答：

1. 不读字幕，联系表还能看出推进吗？
2. 每个语义事件在 cue 前后改变了什么？
3. 动作结束后是否真的留足了阅读时间？
4. 每个真实 scene 是否有显式入口，转场中点是否有主体、可读且完成接力？
5. 实际预览的节奏、缓动、音效和可读性是否与契约一致？
